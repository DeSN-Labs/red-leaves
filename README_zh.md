# red-leaves （红叶）
去中心化社交网络

## 项目愿景
创建一个区块链去中心化社交网络开源项目，实现用户可以在这个社交网络上自由创作并获取收益，自由查看他人创作的内容，自由打赏或购买数字化资产，涉及收益部分由区块链结算，类似抖音或者小红书，但是创作者的收益没有平台抽成，创作的内容不受审查，获取的收益可以变现，整个网络没有官方广告。
这里说的网络节点，是希望把互联网上的大量的NAS设备连接起来组成一个网络。通常NAS设备位于NAT后方。当然程序也可以运行在其他类型的设备之上，共同组网。
项目需要由如下几部分构成：
1. 一个L2区块链网络，发行自己的代币，或者用已有的L1代币桥接过来，实现安全和结算；
2. 一个P2P社交网络，用户创作的内容可以定向或不定向广播，其它用户可以自由选择接收或不接收广播内容；
3. 一个社交网络客户端，可以是手机app、web页面或其它形式，实现对社交网络内容的展示和交互。

这个仓库是社交网络部分，主要实现社交信息的创作、传播部分。

## 功能方案
包含以下功能：
1. 用户可以用钱包地址作为身份加入网络，无需注册等操作；
2. 网络会有大量的区块链节点作为应用客户端的服务器；
3. 用户可以凭钱包地址身份在不同服务器之间切换，连接不同的服务器，但是需要设置一个可以信任的常驻服务器，用于处理自己相关的网络数据，切换到其它服务器后社交能力应该做一些限制；
4. 用户可以在该网络关注别的用户、和其它用户单聊、群聊，可以发表自己创作的内容，可以评论其他人发布的内容；
5. 用户创作的内容可以选择发布范围，如全网/关注的人/好友/特定账号/私密等；
6. 用户可以选择自己接收的内容范围，如任意广播内容/关注的人/好友等，如果某个用户被加入自己的黑名单，则再也不会被动看到该用户的内容；
7. 用户在阅读别人创作的内容时，可以打赏；
8. 用户发布的帖子不设置价格或付费解锁，付费交易内容放到用户橱窗；
9. 用户可以在社交网络直播，可以设置为收费直播或不收费直播；
10. 所有的结算都使用我们自己的链的token；
11. 用户除了全网广播外的所有内容都需要加密，传输给特定用户的内容需要用对方的公钥加密；
12. 需要限制传播范围的内容可以用AES加密方式；
13. 网络允许数字资产的交易，将资产加密后，为买家提供解密密钥，有人购买后，将密钥用购买方的公钥加密后提供给买方，不提供退款等操作，如果数字资产体积较大，需要托管给网络上特定的节点：中继节点；（这个功能放到用户商店）
14. 网络需要提供不同角色的节点，如存储提供节点、流量中继节点、公开服务器节点等，这些节点可以通过提供服务获取报酬；
15. 用户在网络上消费流量一般需要付费，设计中用户创作的内容，除了托管到存储节点的，都只保存在常驻服务器，一般可能是在NAT后面的NAS设备，用户查看内容需要使用中继服务的，则需要付费；
16. 创始团队保留铸币权，从而可以获取报酬，但是需要做出规则限制；
17. 用户把内容托管到第三方节点，一般需要付费，托管节点可以设置托管费用；
18. 所有收益没有平台抽成；
19. 聊天时单聊内容用对方公钥加密；
20. 因为我们网络的私密性，大量的信息交换需要经过中继节点，中继节点提供流量服务时可收取费用；
21. 用户可以点赞收藏帖子，收藏的帖子把数据拉取到主服务器（NAS盒子）；
22. 平台或三方服务商可以设置公开的服务器供玩家在不能连接自己的主服务器或没有自己的NAS设备时也能接入网络，服务提供方需要对公开推送的内容做审核以保证合规，私密内容无需审核，三方服务商可以选择收费盈利；
23. 关于代币的设计，应该可以支持其他币种的交易，但是可以设置其他币种交易收取手续费，项目发行的代币交易不收取手续费；
24. 中继服务节点采用订阅制，用户订阅后才可以使用，解决付款的问题，订阅等于给了支付权限；
25. 用户可以创建服务频道，服务频道则是订阅而不是关注；
26. 用户交易可以支持多种虚拟货币，但是对于非项目代币要收取交易手续费；

## 中继节点收费方案
1. 中继节点提供流量中继服务时，按流量计费，流量消费达到阈值后，中继节点要求中继使用者签署支付票据，收集一定数量的支付票据后到网络合约兑换代币；
2. 如果中继使用方不签署支付票据，中继节点停止中继服务，并降低该节点信用等级，惩罚不守信用的节点；
3. 如果中继节点不守信用要求使用者签署不合理的票据，流量使用方可以降低该节点信用等级，中继节点作恶会导致无人使用它的中继服务而间接收到惩罚；

## 技术方案
考虑使用 https://github.com/Sovereign-Labs/sovereign-sdk.git 来实现
1. 考虑所有节点间的p2p连接只使用一条，兼顾L2的p2p和内容传播的p2p；
2. 需要分析哪些内容要上链，哪些内容不上链；

## 区块链部分
1. 采用 op stack 或 zkSync-os 技术栈实现一个以太坊的L2来承载区块链内容，设置 Custom Gas Token 作为代币
2. 在自己的链和以太坊链部署DEX合约实现代币交易，让代币能在区块链市场自由流通
3. 视情况决定是否上中心化交易所

## 方案的优势
1. 创作者的收益无平台抽成
2. 创作的内容不受审查
3. 内容的传播由用户自由选择
4. 创始团队只持有一定量的代币，只有保持代币价值稳定才能获得收益，与网络使用者利益一致

## 开发与仓库结构

NAS 与中继节点已支持可配置级别、文本／JSON 输出及按天轮转的文件日志，见[日志配置](docs/logging.md)。

Rust workspace 包含 `crates/node`（节点）和 `crates/protocol`（协议库）；
`web/` 为独立的测试与本地管理页面，`contracts/` 为 Foundry 合约工程。
`tests/scenarios/` 保存后续多节点联调，`deploy/` 保存部署配置。
架构和协作规则见 [仓库决策](docs/architecture/0001-repository-layout.md)。

```sh
cargo run -p red-leaves
cargo fmt --all --check
cargo check --workspace --locked
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
```

默认 NAS 节点已运行 SQLite 支持的 EOA 钱包认证 API；支持持久 NAS PeerId 和 Web 首次链上登记；已实现本地文本／图文／视频发布、定向加密及接收偏好，帖子不再定价或付费解锁；已接入跨 NAS 范围投递、中继、离线重试、实时收件箱及远程媒体按需读取，节点地址配置见[推送说明](docs/scoped-delivery.md)。使用流程见[发帖说明](docs/posting.md)。绑定流程见[首次绑定 NAS](docs/nas-registration.md)。配置及接口见[钱包登录](docs/wallet-login.md)。Web 使用 Node.js 22.12+，执行
`cd web`、`npm ci`、`npm run dev`；构建使用 `npm run build`。
合约工程使用 Foundry，执行 `cd contracts` 后运行 `forge build` 和 `forge test`；
已实现用户注册合约和测试，部署配置见 `contracts/.env.example`，本地填写 `contracts/.env.profile` 后执行部署脚本；已有本地成功广播回执，独立 RPC 复核状态见 [部署记录](contracts/deployments/base-sepolia.json)。详见各目录 README。

数据库依赖统一使用 SQLx，通过节点 features 选择：

- `nas`（默认）：SQLite，使用 `cargo build -p red-leaves` 构建。
- `relay`：PostgreSQL 与 rustls，使用 `cargo build -p red-leaves --no-default-features --features relay` 构建。

Cargo features 为叠加关系，同时启用将包含两种数据库驱动。`nas` 已实现 SQLite 钱包认证及本地帖子元数据存储；`relay` 已提供电路中继与公开通知转发，PostgreSQL 持久化及流量计费尚未实现。同时启用时运行 NAS 实现。

身份注册设计已确认：链上用户信息仅保存钱包地址、对应常驻 NAS 的 PeerId、内容加密公钥和昵称；头像（含地址、内容标识及哈希）、性别及其他资料通过链下网络获取，私钥不上链。中继入口与服务授权改为链下设计，发现、防重放、公钥轮换与恢复规则待定；注册合约及 Web 首次登记已实现，部署及接口见 [合约说明](contracts/README.md)。详见[数据交换协议](docs/data-exchange-protocol.md)。

NAS 与中继参与的通信方案见[节点通信协议 v0.1 草案](docs/node-communication-protocol-v0.1.md)。[共享协议库](crates/protocol/README.md)已实现有界 Protobuf 帧、确定性 CBOR、握手协商、签名中继路由、EOA 公开事件验签、签名保存声明及文件清单／块完整性检查，并提供参考向量和内存交换测试。NAS 本地发帖新增了签名发布确认、应用密钥保管、定向加密及持久化待投递队列；队列已接入直连／配置中继的应用级投递；DHT 自动发现、服务 grant 及撤销传播仍待接入，见[推送说明](docs/scoped-delivery.md)和[发帖说明](docs/posting.md)。
