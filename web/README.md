# 红叶 Web 客户端原型

TypeScript + React + Vite，Node.js 22.12+。独立构建，不依赖 Rust 启动。

```sh
cd web
npm ci
npm run dev
```

默认入口 http://127.0.0.1:5173。`npm run check` 检查类型，
`npm run build` 产出 `dist/`，`npm run preview` 预览构建产物。

## 当前功能

EOA 钱包签名登录页、左侧导航的关注内容首页、搜索、关注动态卡片网格与创作者单列时间线、创作者筛选、内容详情和当前会话的演示点赞／收藏。
可请求兼容 EIP-1193 的浏览器扩展钱包公开地址；取消、缺失钱包和重复请求有错误提示。
账户、网络变化或钱包断开后返回连接页，并尝试撤销服务端会话；失败时提示会话到期失效。退出不撤销钱包站点权限。

需先启动 NAS（仓库根目录 `cargo run -p red-leaves`）。Web 默认直接请求 `http://127.0.0.1:3000/api`，后端支持 CORS；钱包需选择 Base Sepolia。
配置放 `.env.profile`（模板见 `.env.example`），Vite 配置始终加载 `.env.profile` 的公开 API／合约地址，兼容 IDE 默认 `development` 启动；配置 `VITE_API_BASE_URL` 及 `VITE_USER_REGISTRY_ADDRESS` 后重启，生产构建时设置实际 API 的 HTTPS 地址。
已接入 SIWE 挑战签名认证，使用内存 Bearer 令牌，不使用 Cookie 或本地持久化，刷新需重新登录。
钱包登录成功即将当前 API 服务视为已认证的 NAS，侧栏及“我的 NAS”展示连接状态和 API 地址，可手动检查会话。
发布按钮先调用 `/api/auth/me` 验证连接和会话，再进入发布占位页；内容发布及文件上传接口尚未实现。演示模式不会被标记为已连接 NAS。
登录后各页面顶部显示个人资料登记状态，从认证接口验证节点类型并获取 PeerId，通过钱包查询链上登记。未登记且确认是 NAS 节点时显示 `Register profile` 按钮，用户主动展开昵称／公钥表单，再确认钱包交易；不会自动弹窗或发送交易。等待两区块确认及字段核对。查询失败显示具体错误和重试入口，旧服务缺少身份接口时提示重启 NAS。不会自动提交或覆盖已有登记，认证成功不代表已获得用户数据权限。
浏览器可主动生成并持久化不可导出的 X25519 密钥；清除站点数据会丢失密钥，备份／恢复未实现。流程、配置及限制见[首次绑定 NAS](../docs/nas-registration.md)，认证接口见[钱包登录](../docs/wallet-login.md)。
`npm test` 使用模拟钱包/API 验证登录与退出流程；尚未执行真实钱包扩展端到端验证。
内容列表保留数据源返回顺序，前端不排序；后续节点 API 应按发布时间倒序返回内容。
演示身份不会连接钱包；所有帖子与统计均为演示数据，收藏不会下载到 NAS，刷新后重置。
演示图片来自 Unsplash，字体来自 Google Fonts，需要外网，真实内容后续通过节点 API 获取。
不提供算法推荐；正式手机 App、安全会话和设备授权需另行实现。
