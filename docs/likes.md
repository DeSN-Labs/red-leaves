# 点赞汇集与按需读取

当前实现点赞及取消点赞：用户在自己的 NAS 保存签名动作，持久队列发往作者当前登记的 NAS；作者验签、去重并保存每个钱包的最新状态。其他持帖 NAS 在用户打开详情或点击 Refresh likes 时向作者请求统计，不广播点赞事件，也不枚举全部持帖节点。评论仍未实现，收藏仍是独立的本地演示功能。

## 签名与投递

`social::Action::Like { post_id, enabled }` 是独立链下 EIP-712 动作。`post_id` 为完整 34 字节 SHA-256 multihash，和 enabled、操作者、NAS、网络、nonce、签发时间一起进入规范 CBOR 与签名，不改写原帖，不发送链上交易。

准备和提交经现有 `/api/social/prepare`、`/api/social/commit`；提交消费一次性挑战，验证当前钱包登记的 NAS，返回 `status: saved` 仅说明本地排队完成，不代表作者已接收。每个 `(post_id, owner)` 保留最新待同步状态；更旧的本地提交返回 409。签发时间逐对单调增加，最多允许领先 NAS 时间 120 秒。作者验原签名、网络与当前链上 PeerId 绑定，离线投递不重新套用已消费挑战的 15 分钟过期条件；按 `(issued_at, nonce)` 保留最新状态，重复或较旧事件不重复计数。取消点赞保留禁用记录，旧点赞重放不能恢复计数。

队列状态为 pending、retrying、delivered、denied，按现有最多 4 个出站任务的并发限制执行，失败指数退避、最长 300 秒；重启继续处理，更新状态时绑定具体 payload，旧任务不能覆盖较新的操作。权限拒绝为 denied，不无限重试；作者恢复权限后用户需重新提交新的签名动作。当前每 NAS 最多保留 10,000 对点赞同步状态，每帖最多保留 10,000 个钱包状态（包括取消记录），每帖最多 1,000 条作者拒绝规则。达到上限时拒绝新增，不承诺自动淘汰或无限历史。

## 当前权限

作者在每次接收点赞和返回统计时检查当前规则。本人始终可管理自己的帖子；其他钱包必须同时满足：

- 帖子已发布，符合[作品访问权限](post-access.md)的当前五档规则；作者可在发布后扩大或收紧授权。
- 未被作者当前黑名单或单帖点赞规则限制。
- 关注关系以作者 NAS 已保存的最新有效状态为准。

其他 NAS 的旧正文缓存仍可读取，但不会授予点赞提交或读取权限。撤销后不能继续拉取或提交点赞／取消点赞，既往已接受的点赞不自动从总数中移除。详情的 Likes access 是附加拒绝规则，恢复后仍需满足作品访问权限。

权限检查及统计读取使用同一 SQLite 查询快照；接收写入同样在写入语句中检查规则。权限变更影响之后的检查，不承诺收回已经返回或在授权检查时已获准的数据，也不能删除其他设备已另存的信息。NAS 迁移、链重组及跨节点完整撤销协议仍属后续边界。

## API 与展示

| 接口 | 行为 |
| --- | --- |
| `GET /api/posts/{id}/likes` | 本钱包必须在 NAS 可读到帖子；返回作者汇集的 `count`、本钱包 `liked`、本地尚未确认的 `pending: {enabled,state}` 或 null |
| `POST /api/posts/{id}/likes/access` | 仅当前作者及其登记 NAS 可管理，请求 `{target: "0x…", allowed: false/true}`，限制／恢复点赞提交和读取 |

接口沿用 Cookie／Bearer 会话及来源防护；无帖／无权限统一 404。作者离线、网络或链查询失败返回 503，不回退旧点赞缓存；统计查询成功并不永久授权下次读取。远程请求通过已认证的 libp2p PeerId 发送至作者最新链上 NAS；响应以 AES-GCM 加密、HPKE 封装给查看者当前公钥，AAD 为 `red-leaves/likes/1/{post-id}/{lowercase-viewer}`，中继不读取私密互动内容。

Web 详情显示上次成功拉取的统计及本地待同步状态，按钮签名提交点赞／取消点赞；打开详情或手动刷新按需读取。刷新失败清除统计，避免把旧计数显示为本次成功读取。未自动向其他持帖 NAS 推送点赞更新；已打开页面的数据只在下一次请求时重验权限。远程只返回计数与查看者自己的状态，不返回其他点赞者名单或完整事件历史；计数由作者提供，不是可独立验证的汇总证明，也不承诺一个钱包代表一个自然人。

## 存储与协议

点赞存储在 version 6 上增加 `social_likes`、`social_like_sync`、`social_like_denials` 表，事务性升级并保留已有帖子、关注、身份和投递数据；当前 version 8 另含作品访问权限表，见[权限说明](post-access.md)。空库直接初始化完整结构。更早的付费帖结构继续不兼容，不自动清理用户数据。

应用传输升级为 `/red-leaves/delivery/4.0.0/<chain-id>/<registry>`、`red-leaves/public/4/<chain-id>/<registry>`，包含 `Access`、`Like`、`Likes` 请求与加密的 `Likes` 响应；网络、原始事件签名、Noise 身份和 HPKE 仍分别承担各自校验。所有参与节点需同步升级，旧 v2／v3 节点不协商 v4，任务保持待重试，不降级到公开传输。帖子本身的规范签名和 version 2 对象格式不变，既有帖子投递缓存 AAD 仍为 delivery/2；这里的版本不等于 Relay v2 传输版本。
