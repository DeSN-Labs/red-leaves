# 数据交换协议 v0.1 讨论稿

日期：2026-10-16

## 1. 范围与状态

本文记录已确认的用户常驻服务注册、NAS 定位和权限更新规则，保留社交数据交换的设计入口。“已确认”表示设计决定，不表示已实现或部署。本文不是最终合约 ABI、网络报文或密码协议规范。

产品依据见[产品需求规格说明书](product-requirements.md)，主要关联 FR-010～019、FR-020～028、FR-030～044。未确定的字段和行为不得视为开发定案。

## 2. 网络与身份边界（已确认）

当前所有链上功能使用 Base Sepolia，Chain ID 为 `84532`。身份注册先行，测试代币、打赏及中继结算仍按后续排期开发，不将帖子、点赞和收藏默认上链。NAS 通过可配置 RPC 访问链，不要求运行 L2 验证全节点；对 RPC 存在信任依赖，故障切换策略待定。

长期自建 L2、发行代币为后续方向，技术栈及迁移规则未定。更换 RPC 不等于完成身份、授权和资产迁移。部署与更新需要测试 ETH 支付 gas；NAS 服务密钥可以持有少量测试 ETH，但不获得用户钱包资金控制权。

| 身份／密钥 | 职责 | 权限边界 |
| --- | --- | --- |
| 用户钱包 | 用户身份及绑定控制者 | 绑定、更换、撤销常驻服务；私钥不交给 NAS |
| App 设备密钥 | 经授权签署帖子及用户行为 | 设备授权另行设计，不能由 NAS 服务权限代替 |
| NAS 节点密钥 | 证明连接对端节点身份 | 不代表节点上所有用户，不授予用户行为签名权 |
| 每用户 NAS 服务密钥 | 投递、同步、更新入口 | 不得签署用户帖子、支配用户钱包资金或授权新设备 |

同一 NAS 可服务多个家庭成员，节点身份可以共用，每个用户的服务密钥及授权独立。钱包地址不等于加密公钥；服务签名密钥也不自动作为内容解密密钥。

## 3. 常驻服务注册记录（已确认）

按钱包地址查询所配置网络的注册合约。网络和合约地址共同限定注册表，不能将任意同名合约视为权威。

| 字段 | 概念类型 | 含义与控制者 |
| --- | --- | --- |
| `owner` | 钱包地址 | 查询键、控制者；服务密钥不能更改 |
| `nasPeerId` | 节点身份标识 | 当前常驻 NAS，由钱包设置 |
| `serviceKey` | EVM 授权地址 | 对应该用户的 NAS 服务签名密钥，由钱包设置 |
| `generation` | 非负整数 | 合约维护的授权代次，绑定、更换和撤销时递增 |
| `active` | 布尔值 | 当前绑定是否有效，由钱包操作决定 |
| `relayEndpoints` | 中继入口集合 | 公网中继连接线索，钱包初始化，当前服务密钥可更新 |
| `endpointRevision` | 非负整数 | 当前代次内的入口更新序号，防止过期更新覆盖 |

不登记家庭内网地址、家庭 IP、私钥或访问令牌。字段是语义定义，不是最终 Solidity 类型。入口编码、数量、长度和空值校验待定。记录公开可查询，钱包关联和历史入口不属于私密信息。

授权代次不同于协议版本；入口更新序号不同于社交事件序号。未注册、已撤销和 RPC 读取失败必须区分。

## 4. 操作与状态转换（已确认）

操作名称为语义名称，不是最终函数签名。

| 操作 | 发起者及前提 | 成功后状态 |
| --- | --- | --- |
| 首次绑定 | 用户钱包，尚未注册 | `generation` 从 0 增至 1，设置节点、服务密钥和初始入口，`active=true`，`endpointRevision=0` |
| 更换／重新绑定 | 用户钱包，记录已存在 | 代次加 1，设置新绑定和初始入口，`active=true`，入口序号重置为 0 |
| 撤销 | 用户钱包，绑定有效 | 代次加 1，`active=false`；保留代次，旧字段即使留存也不得用于有效定位 |
| 更新入口 | 当前服务密钥，绑定有效且预期代次、入口序号均匹配 | 仅替换入口，入口序号加 1，其他字段不变 |
| 查询 | 任意查询者 | 返回当前记录，不改变状态 |

无有效绑定时重复撤销应拒绝，不递增代次。失败操作不得部分写入；整数溢出不得回绕复用，最终错误编码待定。

### 4.1 入口更新

服务密钥直接发送交易，逻辑输入为目标 `owner`、预期 `generation`、预期 `endpointRevision` 和新入口。合约依次检查：

1. 记录存在且有效。
2. 交易调用者等于当前 `serviceKey`。
3. 预期代次等于当前代次。
4. 预期入口序号等于当前入口序号。
5. 新入口满足后续确定的格式及资源限制。

通过后原子更新入口并递增序号；失败方重新查询后决定重试，不能盲目覆盖。并发更新使用相同预期序号时至多一个成功。序号不证明入口可达，也不能阻止当前合法服务密钥主动改写入口。

首期不支持代付签名。服务密钥可支付自身交易 gas，不因此获得用户支付、转账或其他授权权限。

### 4.2 更换与撤销

例如首次绑定代次 1，撤销后为 2，重新绑定后为 3，不删除记录再从零开始。即使重新使用相同服务地址，旧代次更新仍然无效。

钱包更换与旧 NAS 更新的先后以链上执行顺序为准：旧更新先执行时可在旧代次内成功，随后被新绑定替换；钱包更换先执行时旧更新必须失败。更改节点身份或服务密钥必须由钱包操作，入口更新不得扩大服务权限。

## 5. 从钱包地址定位 NAS（已确认）

1. 查询指定链和注册合约，区分未注册、撤销、读取失败和有效记录。
2. 获取节点身份、服务密钥、授权代次、中继入口和入口序号；缓存关联网络、合约及读取区块信息。
3. 有已验证直连通道时可尝试直连，否则使用中继入口。NAS 主动连接中继，不要求家庭公网入站地址。
4. 验证对端持有 `nasPeerId` 对应的节点身份，并将当前用户服务授权与连接关联。具体挑战证明、会话绑定及防重放报文待定。
5. 验证通过后交换受保护数据。App 与自己的 NAS 端到端加密，中继不能代替 NAS 证明身份；NAS 间受限内容加密另行细化。
6. 失败时刷新登记并尝试其他入口，仍失败报告不可达，不将登记成功解释为在线。

发现用户不依赖扫码、用户链接或全网资料广播。发现常驻服务和首次授权 App 是两个不同问题。

## 6. 链状态、缓存与撤销传播

已确认：提交交易不等于成功执行；执行成功不自动等于满足应用确认策略，也不代表所有节点刷新缓存。合约执行撤销或更换后，后续旧授权更新失效；其他节点在获知新状态后拒绝旧服务授权。

撤销服务绑定不能删除已合法传播的帖子。链上不可读取时，不能把旧缓存宣称为最新授权或默认接受新绑定。

待定：确认策略、区块状态标签、缓存期限、敏感操作刷新策略、链重组回滚、RPC 分歧、合约地址分发及迁移、历史签名有效性。未确定前不承诺完整实时撤销或最终性保障。

## 7. 社交通信分类及既定行为

| 通信类型 | 示例 | 可靠性方向 |
| --- | --- | --- |
| 控制请求 | 身份验证、查询节点、建立中继通道 | 请求响应、超时和明确失败，报文待定 |
| 社交事件 | 关注、发帖通知、点赞；后续评论与聊天 | 持久化、去重、接收方保存确认、重试 |
| 内容传输 | 图片、视频、文件 | 校验完整性，分块、取消及断点续传细节待定 |

已确认的行为：

- 逻辑目标是接收方 NAS，物理路径可直连或经中继，不要求帖子先推给中继。
- 用户签署帖子和附件清单，自己的 NAS 持久化内容及附件后推送；App 离线后继续投递，NAS 不得签署新用户帖子。
- 首期发送方保存待投递任务，双方 NAS 需要有同时在线时间；中继不默认提供离线信箱。
- 中继收到不等于目标持久化；正文保存、附件下载、用户已读分开处理。
- 帖子不能远程撤回。关注者默认保存可访问的正文，附件按需获取，收藏完整保存至自己的 NAS。
- 发布及接收遵守可见范围、授权和黑名单规则；互动为独立签名事件，最终同步，重试不能重复计数。

## 9. 设计场景检查

以下为后续实现的检查依据，不表示已运行测试。

| 场景 | 预期 |
| --- | --- |
| 首次绑定 | 用户钱包建立代次 1、入口序号 0 的有效记录，其他钱包不能覆盖 |
| 两用户共用 NAS | 节点身份相同，服务密钥独立，A 的服务密钥不能更新 B 的入口 |
| 更换 NAS | 钱包更新节点和密钥并递增代次，旧密钥更新失败 |
| 撤销后重新绑定 | 代次持续递增，不复用旧代次，不删除历史帖子 |
| 旧密钥或旧代次更新 | 更新失败且不部分写入，即使服务地址被复用也一样 |
| 过期入口更新 | 预期序号不匹配时拒绝，查询后再决定重试 |
| 中继不可达 | 刷新登记、尝试其他入口，失败显示不可达，不判断用户不存在 |
| 伪造目标 NAS | 身份或授权验证失败不得交换私密数据；具体测试依赖后续握手设计 |
| 撤销传播延迟 | 合约拒绝后续旧更新，不宣称缓存节点立即获知 |
