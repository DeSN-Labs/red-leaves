# 发布后的作品访问权限

创作者可在 My notes 打开作品详情，在 Work access permissions 中修改权限。作者自己始终可以读取和管理作品；权限针对其他用户。设置保存后，新的正文、媒体和点赞数据请求按最新规则检查。

| 权限值 | 可访问者 |
| --- | --- |
| `none` | 不允许其他人访问 |
| `followers` | 关注作者的人 |
| `following` | 作者关注的人 |
| `directed` | 作者指定的 1–32 个钱包 |
| `public` | 所有人 |

关注关系及作者黑名单以作者 NAS 已保存的最新有效状态为准。网络分区时无法提前得知尚未同步的关注变化；作者黑名单优先于上述公开或群体授权。接收偏好仍单独控制被动收帖，不授予访问权限。

## 缓存与互动边界

按产品约定，其他 NAS **已经缓存的帖子不受权限变更影响**：不删除、不作废，仍可离线解密并读取。仅收到通知而未缓存正文的 NAS，必须在获取正文时通过作者当前权限检查。权限收紧不能收回已交付正文、标题、密钥或用户另存的文件。

媒体当前按需从作者拉取，不在接收 NAS 持久缓存；每次新请求检查最新权限，传输过程中每块还会检查权限和授权版本，权限修改使旧下载令牌失效。已经交付或另存的媒体不作回收。

点赞由作者汇集；提交及拉取统计复用正文／媒体的当前权限查询，并继续叠加单帖点赞拒绝规则。旧正文缓存不能授予点赞数据访问权。作者离线时正文缓存仍可读，但点赞统计返回不可用，不回退旧统计；离线签名点赞可以排队，最终是否接受由作者检查。撤销不自动删去已经接受的点赞。

评论尚未实现。后续评论提交及新增数据拉取须复用 `api/posts/access.rs` 的权限入口，遵循作者汇集和按需增量追加的规则；作者删除不向其他 NAS 同步删除，已保存评论继续保留。旧评论读取不因权限变化而失效，但旧副本不授权继续拉取。详见[评论增量同步](comment-sync.md)；本次没有新增评论接口。

## 接口与身份验证

- `GET /api/posts/{id}/access`：仅作者读取当前 `{level, recipients, revision}`。
- `POST /api/posts/{id}/access`：仅作者提交 `{level, recipients}`，其他等级必须使用空 recipients，指定人不得含重复、作者自身或零地址。每次更新递增 revision，原子更新规则及投递队列。
- `GET /api/posts/{id}?author=0x…`：允许尚未保存该帖的 NAS，依据作者当前链上登记地址主动拉取。页面 Open a shared work 提供入口。拒绝为 404，链查询／网络故障为 503；不会绕过作者权限。

管理接口使用已有 Cookie／Bearer 登录会话及来源防护，要求当前登录钱包是原作者，且作者链上登记的 NAS 为本机。设置不产生新的发帖签名。作品原始签名、内容 ID、发布确认及原始投递名单保持不变；签名中的名单记录初始投递，不再限制作者之后明确扩大的授权。作者 NAS 为权限执行方，不提供独立钱包签名的策略证明；NAS 属于用户信任边界。

远程读取验证 Noise PeerId 与当前链上钱包／NAS 绑定，作者验证查看者的 NAS 身份后，用查看者公钥封装内容密钥；中继不读取应用明文。点赞同样加密返回。`Access` 请求返回当前授权版本供权限查询使用，不能作为永久通行证。权限变化在后续检查时生效，不能撤回已经完成授权检查而返回的数据。

## 持久化与传播

SQLite version 8 新增 `social_post_access`、`social_post_access_recipients` 及投递任务 `access_revision`。version 6／7 事务性升级并保留现有帖子及互动；初始 broadcast 对应 public，following／followers 对应同名动态权限，friends／directed 对应原始指定名单。旧付费帖格式仍不兼容。

权限变更将旧队列任务标记 filtered，并为新范围重新排队；旧任务不能覆盖新版本的投递状态。公开范围广播，指定范围定向通知；关注范围最多主动通知当前 32 人，超过部分及后续新关注者可凭帖子 ID 主动拉取，不承诺自动补投全部历史帖子。已缓存副本不发送删除或失效消息。

应用协议为 `/red-leaves/delivery/4.0.0/<chain-id>/<registry>`，公开主题为 `red-leaves/public/4/<chain-id>/<registry>`。新增 `Access` 请求及版本响应，支持超出初始签名投递名单的新授权；所有参与节点需同步升级，v3 不协商 v4。帖子对象仍为 version 2，缓存加密 AAD 仍为 delivery/2；不改用公开传输，也不重写原始签名。三台物理服务器尚未重新部署此版本。
